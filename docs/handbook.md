## 一、总原则

一套界面看起来是否「高级」，取决于底层规范是否统一，而不是某个组件做得多漂亮。以下三条是全篇的前提：

1. **克制用色**。界面里绝大部分面积应该是黑、白、灰；彩色只留给最重要的动作和信息。一个页面里强调色出现得越少，它就越有力量。
2. **一切尺寸有出处**。字号、间距、圆角、高度都不应该随手填写，而应该从本文的表格里取值。数值统一了，界面自然显得井井有条。
3. **照顾所有人**。文字要能看清（对比度达标）、按钮要能点中（触控面积够大）、键盘要能用（不依赖鼠标），并且尊重系统中「减少动态效果」的设置。

## 二、色彩规范

### 2.1 三类颜色

一套界面只需要三种颜色：

| 类别 | 占比 | 用途 |
| --- | --- | --- |
| 中性灰阶 | 约 90% | 背景、卡片、文字、分割线，承担界面的全部结构 |
| 强调色 | 约 10% | 品牌色或主色，只用于最重要的动作和信息 |
| 语义色 | 少量 | 成功（绿）、警告（黄）、错误（红）、信息（蓝） |

强调色出现得越少越有力量。如果一个页面里有三个红色按钮，主次就消失了。

### 2.2 灰阶的用法

建议准备十一级灰（从最浅到最深），深浅两级为一组搭配使用：

| 用途 | 浅色模式 | 深色模式 |
| --- | --- | --- |
| 页面背景 | 最浅的一级（近乎白） | 最深的一级（近乎黑，但不是纯黑） |
| 卡片背景 | 白色 | 比页面背景略亮 |
| 分割线 | 比背景略深一级 | 比背景略亮一级 |
| 次要文字 | 中灰 | 中灰偏亮 |
| 主要文字 | 近黑（不是纯黑） | 近白（不是纯白） |

- 深色模式不是简单反色：背景不用纯黑、文字不用纯白，层级越高背景越亮。
- 阴影在深色模式下几乎看不见，改用「稍亮的边框」表达层级。

### 2.3 对比度要求（必须满足）

文字与它背后的底色之间，亮度差异要达到以下标准：

| 内容 | 最低亮度差 | 说明 |
| --- | --- | --- |
| 正文小字 | 4.5 : 1 | 低于这个值读起来费力 |
| 大字（约 24px 以上） | 3 : 1 | 大字可以放宽 |
| 图标、边框、开关等控件 | 3 : 1 | 保证看得见、点得中 |
| 正文加强版 | 7 : 1 | 追求极致可读性时使用 |

- 深浅模式要分别检查对比度，浅色达标不代表深色也达标。
- 不能只靠颜色传达信息：错误状态要同时有图标或文字说明，照顾色觉障碍用户。

## 三、文字与排版规范

### 3.1 字号层级

用「1.25 倍」的规律生成一串字号，层级之间拉开明显差距：

| 层级 | 字号 | 行高（约为字号的倍数） | 用途 |
| --- | --- | --- | --- |
| 特大标题 | 48px | 1.1 倍 | 落地页主标题 |
| 一级标题 | 32px | 1.25 倍 | 页面标题 |
| 二级标题 | 24px | 1.33 倍 | 区块标题 |
| 三级标题 | 20px | 1.4 倍 | 卡片标题 |
| 正文 | 16px | 1.6 – 1.75 倍 | 普通内容 |
| 辅助说明 | 12px | 1.5 倍 | 时间、备注，可全部大写 |

- 每个层级的「字号」和「行高」要成对出现，不允许单独调整。
- 标题的字距略微收紧，正文保持默认。

### 3.2 排版规则

- 中文正文的最佳行长是**每行 30–40 个字**；太长眼睛容易疲劳。
- 数字（金额、时间、表格）统一使用等宽数字，否则数字变化时会左右跳动。
- 中文不要使用斜体——中文没有真正的斜体，强行倾斜只会显得廉价。
- 强调用加粗或变色，不要用下划线（下划线容易被误认为链接）。

## 四、间距与栅格规范

### 4.1 间距刻度

所有间距（元素之间的空隙、内边距）只允许使用 4 的倍数：

**4 · 8 · 12 · 16 · 24 · 32 · 48 · 64**（单位 px）

| 场景 | 建议间距 |
| --- | --- |
| 组件内部（文字与边框之间） | 4 – 12px |
| 组件与组件之间 | 16 – 24px |
| 区块与区块之间 | 48 – 96px |

间距的远近代表关系的远近：相关的元素靠近，无关的元素拉开。

### 4.2 栅格

- 页面内容建议限制最大宽度（阅读类约 672px，应用类约 1152px），左右留白居中。
- 列数随屏幕宽度变化：手机 1 列、平板 2 列、桌面 3–4 列。

## 五、尺寸与圆角规范

### 5.1 高度

| 元素 | 高度 |
| --- | --- |
| 密集工具栏里的按钮 | 32px |
| 常规按钮 / 输入框 | 36px |
| 主要按钮 / 大按钮 | 44px |

### 5.2 触控目标

**任何可以点的东西，实际可点面积不能小于 44×44px**（手指能舒服按中的最小尺寸）。

- 图标在屏幕上可以画得只有 16–24px，但要在它周围补一圈透明区域，把可点面积撑到 44px。
- 相邻的两个可点击元素之间，至少留 8px 空隙，防止误触。

### 5.3 图标与头像

| 项目 | 尺寸 |
| --- | --- |
| 图标 | 16 / 20 / 24px（行内 / 按钮 / 大图） |
| 头像 | 24 / 32 / 40 / 56px（行内 / 列表 / 页面 / 个人主页） |

### 5.4 圆角

| 元素 | 圆角 |
| --- | --- |
| 小元素（开关、小按钮） | 6px |
| 卡片 | 12px |
| 弹窗 | 16px |

- 圆角种类一个界面不超过三种。
- 元素里再套元素时，里面的圆角 = 外面的圆角 − 两者之间的间距。

## 六、阴影与层级规范

### 6.1 阴影

- 阴影要「几乎看不见」：多层极淡的黑色叠加，而不是一大坨深色。
- 层级越高阴影越明显：卡片几乎无阴影，弹窗用最重的阴影。
- 深色模式下阴影不可见，改用边框亮度区分层级。

### 6.2 层级（谁压在谁上面）

| 层级 | 数值建议 | 典型元素 |
| --- | --- | --- |
| 页面内容 | 0 | 普通内容 |
| 悬浮卡片 | 10 | 鼠标悬停时浮起的卡片 |
| 下拉菜单、气泡 | 20 | 点按钮弹出的菜单 |
| 粘性头部、侧边栏 | 40 | 吸顶的导航 |
| 遮罩 + 弹窗 | 50 | 半透明黑底 + 对话框 |
| 全局提示（Toast） | 60 | 右下角的消息，永远在最上 |

- 层级数值全站只允许这 6 档，且用变量统一管理，禁止随手写大数字。
- 半透明遮罩出现时，比它层级低的内容都不应该可以点击。

## 七、动效规范

### 7.1 时长

| 场景 | 时长 | 说明 |
| --- | --- | --- |
| 悬停、按下、变色 | 150ms | 越快越「跟手」 |
| 菜单、弹窗出现 | 200 – 300ms | 从小到大 + 淡入 |
| 退出 | 比进入快 20% | 干脆利落 |
| 页面转场 | 400 – 500ms | 大面积变化才需要 |

### 7.2 规则

- 只对「位置、大小、透明度」做动画，不要对宽高、颜色以外的属性做动画——否则会卡顿。
- 出现用「先快后慢」的节奏，退出比出现更快，界面才有干脆感。
- 所有动效都要尊重系统的「减少动态效果」设置：用户关闭动效时，界面应立即呈现最终状态。
- 装饰性动效要克制：一个页面最多一两处。

## 八、响应式与断点规范

### 8.1 断点

| 名称 | 屏幕宽度 | 典型设备 |
| --- | --- | --- |
| 手机 | 小于 640px | 竖屏手机 |
| 平板竖屏 | 640px 起 | 平板、大屏手机横屏 |
| 平板横屏 | 768px 起 | 平板 |
| 笔记本 | 1024px 起 | 笔记本、小显示器 |
| 桌面 | 1280px 起 | 台式机显示器 |

- 内容放不下时才切换布局，不要死记设备型号。
- **从手机开始设计**，先保证小屏可用，再逐级向大屏增强。

### 8.2 常见转换

| 桌面端 | 手机端 |
| --- | --- |
| 多列表格 | 转为卡片列表 |
| 侧边栏 | 抽屉 / 底部导航 |
| 居中弹窗 | 底部面板 |
| 悬停展开 | 点击展开 |

### 8.3 底线

- 320px 宽（最小的现代手机）不允许出现左右滚动。
- 触屏上没有「悬停」：所有悬停效果必须有点按的替代方案。

## 九、常用组件设计规则

### 按钮类

- 一个页面里「主要按钮」只出现一次，其余用次要、描边样式。
- 按下时有轻微缩小反馈；加载中禁止重复点击并显示转圈。
- 危险操作（删除）用红色，并且必须二次确认。

### 输入类

- 输入框由四部分组成：标签、输入区、帮助文字、错误提示；标签永远在上方。
- 错误提示出现在字段正下方，红字 + 图标，并随输入实时更新。
- 密码框必须提供「显示 / 隐藏」切换；强度反馈要在输入时就给出，而不是提交后才报错。
- 选项在 4–10 个用下拉；超过 10 个或需要搜索时用可输入的下拉。
- 日历默认定位到当前月份；今天的日期要有特殊标记。

### 导航类

- 当前位置用颜色和字重区分，不加彩色高亮块。
- 层级超过四层用面包屑；步骤少于六个用步骤条。
- 移动端底部导航的入口不超过 5 个。
- 通知入口带未读标记；未读信息要有明确的视觉提示。

### 反馈类

- 操作成功的轻提示 3 秒左右自动消失；错误提示要等用户处理。
- 加载超过 300ms 才显示加载动画，避免一闪而过。
- 列表为空时给出解释和下一步动作，不要留白。
- 弹窗打开时，背景页面不能滚动；按 Esc 应能关闭。

### 数据展示类

- 数字右对齐并使用等宽数字；文字左对齐。
- 表格去掉竖线，只保留极淡的横向分隔。
- 空数据时显示空状态（图标 + 说明 + 行动按钮），不要留白。

## 十、无障碍要求

无障碍不是附加项，而是规范的硬性要求：

1. **对比度**：所有文字满足第二章的标准；不能只靠颜色区分状态（错误要同时有图标和文字）。
2. **键盘**：所有操作都能只用键盘完成；键盘焦点要有清晰可见的外框。
3. **触控**：可点面积 ≥ 44×44px；相邻可点元素间隔 ≥ 8px。
4. **读屏**：图标按钮要有文字说明；弹窗要标注「这是对话框」；重要变化要主动告知。
5. **动效**：尊重系统「减少动态效果」设置。
6. **表单**：每个输入框都要有标签；错误要说明原因和解决方式。

## 十一、设计走查清单

上线前逐条检查，全部通过才算完成：

**层级**
- [ ] 页面只有一个一级标题，标题层级不跳级
- [ ] 主按钮每屏只出现一次
- [ ] 重要信息在视线上方（左上到右下）

**一致性**
- [ ] 同类元素的尺寸、圆角、间距完全一致
- [ ] 图标风格统一（全部线性或全部面性）
- [ ] 按钮文案用动词，语气一致

**反馈**
- [ ] 所有操作 100ms 内有视觉反馈
- [ ] 异步操作有加载态，完成后有结果提示
- [ ] 错误信息说明原因和解决方式

**无障碍**
- [ ] 对比度 ≥ 4.5:1，且不仅靠颜色传达信息
- [ ] 键盘可完成全部操作，焦点清晰可见
- [ ] 图标按钮有文字说明

**响应式**
- [ ] 320px 宽度下不出现左右滚动
- [ ] 触控目标 ≥ 44×44px
- [ ] 悬停效果在触屏上有替代方案

**性能**
- [ ] 动画只使用位移和透明度
- [ ] 图片懒加载且尺寸固定（避免加载时跳动）
- [ ] 首屏无布局跳动
